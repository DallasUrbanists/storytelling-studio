## Observed failure and correction

The retained host log at `.local/research-schema-EGRjIE/gate-b.log` shows a 404
for `/tests/fixtures/synthetic-story/assets/bridge-style.json?import&url`,
followed by `Vue preview did not mount`. Its Gate B receipt is under
`.local/render-contract/D1-09-2026-11-13T13-16-44-539Z-f869c9ed-389b-41ad-901d-d5a9f483bcf9/`.
That run reached the portrait Vue `missing-style` case after image comparisons;
the failure was not a missing fixture file.

Vite loads a JavaScript module exporting each asset URL before the adapter
fetches the resource bytes. The harness previously matched both requests by
filename, so its intentional missing-style response also broke the module
graph. `tests/render-contract/browser.mjs` now uses CDP's resource type to
target only the adapter's `Fetch` requests, for both fault injection and pinned
resource hashing. Script imports continue normally; required asset failures
still receive the original fault response or remain held for the deadline case.

The new regression in `tests/render-contract/browser.test.mjs` exercises the
installed pinned CDP session for all five existing fault cases. It checks that
Vite's `?import&url`, `?url`, and timestamped URL modules continue, do not count
as asset hashes or fault injections, and leave the subsequent raw-resource
fetch subject to its original failure. Existing text/binary resource hashing
and screenshot response tests remain in place.

Only those two harness files and this receipt were changed in this repair.
The project fixture, parity checks, seek order, tolerances, package manifest,
