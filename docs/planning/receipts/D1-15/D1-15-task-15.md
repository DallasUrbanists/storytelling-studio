## Implemented security contract

`apps/local-service/src/server.ts` constructs a Node HTTP server. Its existing
`server.mjs` launcher import delegates to that implementation. Construction
does not listen, create storage directories, start children or fetch resources.

| Boundary | Actual behavior |
| --- | --- |
| Bind | Only `127.0.0.1`; numeric port 0 selects an ephemeral port. Both construction and subsequent `listen` calls reject remote/wildcard/DNS/IPv6 hosts, pipes and file descriptors. Omitted host still binds to `127.0.0.1`. |
| Request authority | Peer must be `127.0.0.1`; Host must exactly match `127.0.0.1:<actual-port>`. Forwarded authority headers confer no trust. Duplicate Host, Origin or Authorization headers fail. |
| Origins | Accept the exact service origin and at most one launcher-configured studio origin. A studio origin must be a canonical HTTP origin on `127.0.0.1` or `localhost`. Reject other ports, suffixes, opaque `null` origins, credentials and wildcard configuration. Reject `Sec-Fetch-Site: cross-site`. |
| Session | All `/api` routes, including reads and readiness, require `Authorization: Bearer <session-token>`. A session token has 32 random bytes encoded as 64 lowercase hex characters; equal-length comparison uses `timingSafeEqual`. The launcher may supply a fresh token or construction generates an inaccessible fallback. No HTTP token discovery, cookie, URL token, logging or response token exists. |
| Mutations | Require an allowed Origin in addition to the token. A native client may omit Origin for reads only. No CORS grants or preflight authorization are exposed; browser integration must use the planned same-origin proxy. |
| Request resources | Default JSON ceiling is 1 MiB; trusted startup configuration may lower it. Check declared length before reading and counted bytes while streaming, including incomplete chunked requests. Require uncompressed UTF-8 `application/json`. Reject bodies on GET/HEAD. Headers are capped at 8 KiB; header/request timeouts are 5/10 seconds, checked every second, with a 10-second socket idle timeout. Responses close the connection; there is no unbounded rejected-body drain. |
| Paths | Routes match raw canonical paths, without URL normalization or decoding. Queries, encoded separators/dot segments, backslashes, absolute-form URLs and duplicate slashes fail. Project/revision IDs contain 1–128 ASCII letters/digits/underscore/hyphen and begin with a letter/digit. |
| Storage | `storageRoot` resolves startup configuration once relative to the checkout, defaulting to `.local/storytelling-studio`. Explicit `dataDirectory` takes precedence over `STORY_STUDIO_DATA_DIR`. Existing symlinks/junctions and non-directory ancestors fail. The internal `storageDirectory` helper accepts only fixed areas and opaque IDs, rejects reserved Windows device names and checks existing directory chains. No HTTP route takes a root, filename or URL. |
| Output | Validate project documents with D1-03 `parseProject`. Validate exact request/envelope/summary fields locally; shared API-envelope schemas do not exist yet. Check envelope ownership and requested revision IDs. Return safe `{code, message, details, retryable}` errors, with empty details and allowlisted codes/statuses. Internal errors expose no exception text. HTTP parser failures may use Node's generic HTTP errors before routing. Responses set no-store, nosniff and a restrictive CSP. |

These controls protect the HTTP interface against unrelated browser origins and
accidental authority/path misuse. They do not isolate hostile processes running
as the same OS user. Directory checks do not prevent a same-user process from
replacing directories between a check and a future filesystem operation.
Future asset/import implementations must validate their own file operations;
this slice does not provide a general race-safe file-opening API.

## Available routes and remaining integration

`GET /health` remains an unauthenticated, authority/origin-checked liveness probe
for D1-02. It returns only `{status: "ok"}` and does not claim database readiness.
Authenticated `GET /api/health` reports runtime/schema/database readiness,
returning 503 when no ready repository exists.

The implemented project boundary provides these adapter-backed routes:

- `GET /api/projects`: validated summaries sorted by descending update time,
  then ID. More than 1,000 results fail rather than silently truncate.
- `POST /api/projects`: exact `title` (1–200 characters) and opaque
  `clientMutationId`; validated revision envelope, status 201.
- `GET /api/projects/:projectId` and
  `GET /api/projects/:projectId/revisions/:revisionId`: validated revision
  envelope or 404. A mismatched repository result is an internal error.
- `PUT /api/projects/:projectId`: exact `expectedRevisionId`,
  `clientMutationId`, and validated `document` with matching project ID.
  A typed repository revision conflict produces a redacted 409.

The tests inject a synthetic repository. Production construction has no
repository, so project routes return 503 after authorization/validation.
D1-16 must implement durable SQLite transactions, actual optimistic concurrency,
retry/idempotency retention, immutable revisions and recovery. This change does
not implement those behaviors through an in-memory substitute. Repository
construction must use the trusted resolved root, never request fields.

The current development launcher calls the service without session or repository
options. Its health probe remains usable, but it cannot perform project API
requests. Supplying a fresh per-run token, preserving the exact Origin through a
same-origin studio proxy, and securely delivering the token to the authoring
client remain integration work. The fallback token is intentionally unavailable
to callers. No UI, proxy, renderer resource route, upload, arbitrary file reader,
outbound URL proxy or network fetch is introduced here.

### Timestamp ordering review repair

The November 13 PR follow-up reproduced the summary ordering defect through an
authenticated `GET /api/projects`: a timestamp without milliseconds sorted ahead
of a later instant with milliseconds. The service now compares parsed timestamps
numerically in descending order and uses the existing ID comparison when the
instants match. Response timestamp strings and validation remain unchanged.

The added regression checks `.999Z`, `.001Z`, `.000Z`, and `Z`, a preceding
second, and the ID tie-breaker for equivalent instants in both input orders.
The focused regression failed before the comparator repair. After the repair,
`node --test --test-isolation=none tests/persistence/security.test.ts` passed
