## Shutdown ownership

The foreground process creates `.local/lifecycle/record.json` exclusively and
holds its file handle until both stubs and the read-only status listener close.
The stop command checks the checkout path, process ID, instance ID, and file
identity against the running status listener before setting the request flag
through its own open handle. The foreground process unlinks the verified
record after closing the listeners and acknowledges completion on the old
handle. A later instance uses a different file. The stop command never sends a
signal to a PID or issues an HTTP shutdown request.

The shutdown signal uses the checkout's existing write permissions. A checkout
writer can request shutdown. The implementation leaves host ACLs, repository
permissions, and credentials untouched. Verification covered the local Windows
filesystem. A force-terminated process leaves its record for manual inspection
and removal after confirming that the owner has exited.
