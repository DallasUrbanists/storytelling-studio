# D1-02 follow-up verification

The review of [attempt D1-02-20261111-02](D1-02-20261111-02.md) identified a
race between verifying the lifecycle record's file identity and removing its
pathname. An old foreground process could remove a replacement instance's
record if the pathname changed in that interval.

The revised lifecycle retains numbered records in `.local/lifecycle/`. Each
start verifies the latest record is stopped, then uses an exclusive create to
claim the next number. Each foreground process marks completion through its
retained handle after closing its listeners. Shutdown performs no filesystem
deletions. A crash leaves an active record for manual inspection. The checkout's
existing file permissions authorize access to its records.

The Windows probe repeated both npm start/stop cycles, both port collisions,
the concurrent stop test, and the other-checkout and data-preservation checks.
It also confirmed stale and copied records fail closed. In the added regression,
the probe moved a live record and started a replacement instance at the exact
original pathname. It delivered the stop request through the first instance's
previously opened handle. The old instance exited, its moved record showed
completed shutdown, its ports could be rebound, and the replacement record
bytes and process were unchanged. A separate concurrent-start probe confirmed
that exactly one of two simultaneous starts claimed the next generation.

Verification ran on Windows using Node 24.22.1 and npm 11.19.1. The dynamic
probe ran outside the sandbox for loopback access. The ignored worktree script
is `.local/d1-02-generation-probe.mjs` with SHA-256
`814ef1acfa9e7017c292e18f5b5e17c7d4964cda16684dbe644a033d1f7f09e5`.
The tested `scripts/dev.mjs` SHA-256 is
`1ae5d75a94f0793bde0e253f4f95318cf0a60f5807041b376b62845a743b3870`.
The worker worktree's lint, typecheck, and documentation checks passed.
The coordinator owns final verification with the currently merged unit suite.
