## Implemented behavior

`npm run render:fixture` now has a local implementation. Full composition
rendering remains unverified in this sandbox. `--help` describes these modes:

```sh
npm run render:fixture
npm run render:fixture -- --format portrait
npm run render:fixture -- --format landscape
npm run render:fixture -- --format portrait --frames 0,1,149,150,299
```

The default requests both formats sequentially. `--frames` produces diagnostic
PNGs only and never passes the full-video gate. It preserves the supplied
frame order and duplicates. Unknown or repeated flags, missing values, and
noninteger or out-of-range frames fail before tooling runs.

Each render invocation prints a timestamp/UUID run ID and writes
`out/verification/RUN_ID/receipt.json`. The run has separate `frames/`,
`videos/`, `partial/`, and temporary directories. The receipt is initialized
before argument validation and updated by atomic replacement. Failed jobs
retain their error and nonpassing gate status. A video stays in `partial/`
until inspection, complete decoding, and representative-frame checks pass;
only then does it move into `videos/`. Each verified video has its own receipt
entry. Both formats must pass for that invocation's full-video gate to pass.
An interrupted run retains a running receipt and cannot claim acceptance.

The runner validates and hashes the synthetic document and each declared asset,
records a content-addressed fixture revision, and passes that parsed project
explicitly as composition input. It bundles the existing entry point with the
local style, licensed Inter font, and installed MapLibre worker. It requires
the installed Remotion packages and Windows x64 compositor at `4.0.542` and
requires `GSTORY_CHROME` to name an absolute installed browser path. It does
not download a browser or fall back to a system media executable. MapLibre
rendering uses `swangle` and video concurrency 1.

The full-video path requires H.264/yuv420p, exact variant dimensions, 30 fps,
ten seconds, and 300 frames counted by FFprobe. An independent FFmpeg decode
must finish without errors and report 300 frames. Frames 0, 1, 149, 150, and
299 are rendered as source PNGs and extracted from the completed video as
decoded PNGs. PNG signatures, dimensions, hashes, evaluated state hashes,
and video metadata/hashes are retained. Decoded samples must not all be
identical. Those checks do not establish pixel parity, visual correctness, or
human playback review; the receipt explicitly leaves those claims unverified.

The receipt also records source commit, tracked-diff hash, implementation
file hashes, schema/core versions, runtime/package/browser/media-tool details,
asset-manifest and worker hashes, requested frames, stage/request context,
elapsed time, and failures. Browser processes are closed, and temporary
environment settings are restored, including on failure.

The root manifest's duplicate `scripts` properties were consolidated while
preserving the effective existing commands. The bundler is pinned as a root
development dependency at `4.0.542`; npm generated the lockfile from cached
public package metadata and tarballs. Existing package versions were preserved.
No binary is redistributed by this change; the prior compositor license and
distribution limitations still apply.
