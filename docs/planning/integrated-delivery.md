## Application boundaries

The candidate is Windows x64 first. It uses Node 24.22.1, npm 11.19.1, and pinned
Remotion 4.0.542. The narrow browser adapter preserves Chromium's sandbox and
checks that exact renderer version before using its private launcher; upgrades
require revalidation. Its debugging listener and the application service bind
to loopback. Browser clients do not receive the service's mutation credential.

The implemented render resource profile uses retained GeoJSON, inline map
styles, and the local Inter font. Remote map tiles, sprite/glyph services,
aerial-media compositing, a local walkshed routing engine, and public API
automation remain unavailable. Historical and income comparisons require
compatible evidence; the application rejects unsupported median allocation
instead of inventing a result. These boundaries retain the product plan's
conditional and deferred items.

Project documents are limited to approximately 1 MB. Original evidence files
remain content-addressed assets; geometry imports have additional feature and
position limits. Long or geographically extensive films need deliberate
extracts and resource sizing. Automated checks do not establish unlimited
project size, accessibility conformance, or every GPU/driver combination.

## Verification

The fresh installation, complete application checks, production build, and
browser checks passed on Windows x64. The frozen rendering gate passed 272
frame captures, 304 comparisons, and 20 deliberate resource failures, then fully
decoded both 300-frame fixture videos. A separate authored map and roadway
project exported and decoded all 90 frames in both formats. Package round-trip,
cancellation, and fresh start/save/stop checks also passed.

The receipt distinguishes the frozen source hashes from subsequent removal of
redundant terminal blank lines. Full application checks were repeated after
that formatting cleanup. No source changed during the accepted rendering run.

The [machine-readable acceptance record](receipts/integrated-delivery.json)
records actual commands, results, source hashes, tool versions, and output
metadata. Render outputs, browser profiles, caches, and private project files
remain outside Git.

Reproduce the software checks with `npm run check`,
`npm run build:studio`, `npm run test:render-contract:unit`, and
`npm run test:render-contract`. Configure the installed browser in `.env`
before the rendering command. The last check compares two fresh sessions of
each host and format, including shuffled seeks and missing-resource failures,
then decodes both complete fixture videos.

A human visual and editorial review of the final production film remains a
separate factual acceptance step. No such approval is asserted by this change.

## Complete the Maple Avenue production

The software can receive these inputs together as one production pass:

- Supply authoritative or clearly qualified Dallas, DART, landmark, Oak Lawn, and Maple corridor geometry, with original files, dates, and publication rights.
- Supply the 600-second walkshed and its real network evidence, then record technical review of origins, crossing barriers, and routing assumptions.
- Run the matching population inputs against the approved study area and record a named review of coverage, method, period, and wording.
- Supply documented or explicitly assumed existing and proposed roadway dimensions, segment breaks, and the final mapping.
- Confirm the invitation text, any imagery rights, source credits, and editorial approval; then export both formats and the portable project for final playback review.

These are production evidence and owner decisions, not separate implementation
tickets. The final Maple pilot remains incomplete until its actual inputs and
approvals exist. This PR does not close the backlog issue by issue, activate
the old controller, or claim a production milestone from synthetic fixtures.
